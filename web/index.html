InfinityHook leverages the HalPrivateDispatchTable.HalCollectPmcCounters pointer inside the Windows ETW subsystem to intercept system calls at the kernel level— fully compatible with Windows 11 and PatchGuard (PG) enabled.

How It Works
The call chain from a user-mode syscall to our hook callback
User syscall
→
KiSystemCall64
→
EtwTraceSiloKernelEvent
→
EtwpLogKernelEvent
→
EtwpReserveWithPmcCounters
→
HalCollectPmcCounters ← our hook
1

Steal the pointer

Locate HalPrivateDispatchTable inside ntoskrnl.exe's .data section and overwrite the HalCollectPmcCounters slot with our callback. This does not trigger PatchGuard because the dispatch table is writable by design.

2

Enable NT Kernel Logger

Call ZwTraceControl to start the NT Kernel Logger session, which activates the ETW syscall-tracing path that leads to our hook.

3

Configure PMC counters

Use ZwSetSystemInformation(SystemPerformanceTraceInformation, …) to attach a PMC counter and set the syscall hook-ID (0xF33). This forces EtwpReserveWithPmcCounters to be reached on every syscall event.

4

Locate the syscall routine on the stack

Inside the callback, walk the kernel stack and search for the magic number pattern left by EtwpReserveTraceBuffer to find the pointer to the original syscall routine.

5

Replace the target syscall

Overwrite the located stack slot with your own function pointer. The original pointer is saved so you can forward calls to preserve normal system behaviour.

Key components of the driver
🔌

EtwInitializer

Configures the NT Kernel Logger and PMC counters. Calls open_pmc_counter() to reach the ETW hot path on every syscall.

🎣

EtwHookManager

Installs and removes hooks. Maintains a table of (syscall-id → handler) pairs and dispatches callbacks from the ETW context.

🛠

EtwHookUtils

Pattern-scan helpers for HalPrivateDispatchTable and the stack magic-number search used to locate the live syscall pointer.

📋

SysInfoManager

Wraps ZwQuerySystemInformation to expose EtwpDebuggerData and resolve the logger-id needed for PMC configuration.

🗂

kstl helpers

Minimal kernel-mode STL shim — kalloc<T>, pool wrappers, and logging macros used throughout the driver.

🛡

PatchGuard Safety

All modifications target writable data pointers in .data sections. No code patching, no SSDT modification—PG remains silent.

Usage
Hooking a system call with InfinityHook in three steps

The snippet below shows how to intercept NtOpenProcess. Place this in your driver's DriverEntry after calling EtwInitializer::init(). 

// 1. Define your hook function (same signature as the original)
NTSTATUS HookNtOpenProcess(
    PHANDLE            ProcessHandle,
    ACCESS_MASK        DesiredAccess,
    POBJECT_ATTRIBUTES ObjectAttributes,
    PCLIENT_ID         ClientId)
{
    // Custom logic here – e.g. block access to protected processes
    if (IsProtectedProcess(ClientId))
        return STATUS_ACCESS_DENIED;

    // Forward to the original syscall
    return OriginalNtOpenProcess(
        ProcessHandle, DesiredAccess, ObjectAttributes, ClientId);
}

// 2. Install the hook inside DriverEntry
NTSTATUS DriverEntry(PDRIVER_OBJECT DriverObject, PUNICODE_STRING RegistryPath)
{
    // Initialise ETW + PMC
    EtwInitializer::init();

    // Register hook: syscall index 0x0025 == NtOpenProcess
    EtwHookManager::installHook(
        0x0025,
        reinterpret_cast<PVOID>(&HookNtOpenProcess),
        reinterpret_cast<PVOID *>(&OriginalNtOpenProcess));

    DriverObject->DriverUnload = DriverUnload;
    return STATUS_SUCCESS;
}

// 3. Remove the hook on unload
VOID DriverUnload(PDRIVER_OBJECT DriverObject)
{
    EtwHookManager::removeAllHooks();
    EtwInitializer::shutdown();
}

Known limitations
  • Direct kernel NtXxx calls (bypassing the syscall stub) are not intercepted.
  • EtwpMaxPmcCounter may be 1 on some VMs; the driver attempts to patch this value.
  • Anti-cheat software (EAC, BE) that also hooks ETW may conflict.
FAQ
Common questions about the ETW hook technique
Why not use SSDT hooking?
Modifying the System Service Descriptor Table (SSDT) is detected and reverted by PatchGuard within seconds on modern Windows. The ETW pointer-swap technique targets a writable data structure and is not monitored by PG.
Can this be detected by anti-cheat software?
Kernel-level anti-cheat engines (EAC, BattlEye) perform their own integrity scans. While the hook itself is PG-safe, a sufficiently advanced AC may detect the HalPrivateDispatchTable modification or the abnormal PMC configuration.
Does it work on ARM64 Windows?
The current implementation targets x86-64 only. ARM64 has a different syscall path and a different HAL dispatch table layout; porting is theoretically possible but not yet implemented.
What is hook-ID 0xF33?
0xF33 is the ETW kernel-event hook-ID for syscall entry events. Setting this ID via EtwpUpdatePmcEvents tells the ETW subsystem to invoke EtwpReserveWithPmcCounters on every syscall, which is exactly the code path that calls HalCollectPmcCounters—our hook point.
